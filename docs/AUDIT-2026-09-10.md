## 1. Performance — why opening a game felt slow

Profiling (native, warm caches): per-rerun module init ~160ms; cold game-open
compute ~40ms (project_game 10-15ms/team, sgp ~0ms, hit_rate ~10ms/game).
**Server compute was never the bottleneck. The architecture was:**

| # | Root cause | Status |
|---|---|---|
| 1 | Any widget interaction reran the FULL page incl. every open game | **Fixed** — `render_game` now runs in `@st.fragment`; interactions rerun only that game |
| 2 | `db.line_history` = live Turso roundtrip per open game per rerun | **Fixed** — `_line_history` cached 10 min |
| 3 | ESPN circuit breaker *raised* instead of serving stale cache (30 min of empty data after one 403) | **Fixed** — `_get_json` serves stale cache when circuit open |
| 4 | 30s network timeouts on interactive paths (worst case ~100s frozen rerun on Odds API hang) | **Fixed** — timeout 15s; stale fallback after |
| 5 | All 8 tabs render eagerly per open game (st.tabs is eager) | **Proposal** — lazy-render tab bodies (see §5) |
| 6 | Rams projections silently EMPTY (see §3) — looked like "props not loading" | **Fixed** |

## 3. Correctness — the biggest catch

**Rams LA→LAR: latent bug, half-handled.** `load_games` normalizes `LA→LAR`
(data.py:65-67) and logos alias it (display-only), but `load_player_stats`
did NOT — CSV keeps `team=="LA"`. `project_game` filters `ps.team=="LAR"` →
empty → **zero Rams players, zero warnings, in every Rams game** (props tab,
SGP legs, and their opponents' defensive multipliers).
Reproduced: `project_game("LAR")` → 0 players; `("LA")` → Stafford, K.Williams,
Corum, Nacua, Adams.
**Fixed** in `load_player_stats` (team + opponent_team replace); verified all
5 Rams project and def mults align. Note: analytics.py:70 timezone map still
uses "LA" — works today, normalize for consistency during V2.

## 4. V2-readiness (nflverse data upgrade)

- **Loader pattern**: `_get_json` pattern (TTL + atomic write + stale fallback)
  is the right shape, but JSON-only. V2 needs a `_get_df()` analog
  (CSV + parquet via pyarrow) with aggregate-then-delete for pbp. Thin
  generalization, not a rewrite.
- **Snap-share seams** (props_model.py): two clean slots, no rewrite —
  (1) usage groupby ~:120 (season-average → recency-weighted snap-share),
  (2) vacated/boost ~:131-135 (usage → snap share redistribution).
  Landmines: join on player_id never name; dedupe snaps to one row per
  player-week before merging on (season,week); replace usage scale EVERYWHERE
  in the loop; snap share must inherit recency weighting.
- **Props disk cache** survives NGS unchanged (raw API payload, computed
  downstream). If caching computed projections later, version the filename.
- **Unweighted 2-season volume mean** (props_model.py:~120) ranks players
  without recency while projections use recency weights — fold the fix into
  V2 snap-share slot 1 (don't patch v1).

## 7. The actual "site got slow today" root cause (found 2026-09-10 PM)

Main Odds API key hit its monthly quota (**499/500, OUT_OF_USAGE_CREDITS**, HTTP 401)
mid-afternoon. Every `odds_api_lines` call then did 3 fast-failing attempts with
retry sleeps of 1.5+3+4.5s ≈ **9.5s of pure sleeping, paid on every rerun**
(page load, game open, page nav) before falling back to the stale cache — plus
~1.6s per ESPN 403 window. That is the 15s-load / 5s-action Jeff reported.

**Fixed:** `_get_json` now has an Odds-API circuit breaker — a 401/429 opens a 6h
breaker (one fast failure, then stale cache served instantly; verified 9,570ms → 5ms)
and the retry loop no longer sleeps after the final attempt.

**Structural issue (needs Jeff's decision):** free tier = 500 credits/month, but
three environments (native app, Docker, Streamlit Cloud) each keep their own 45-min
cache + value-radar cron — the fetch math no longer fits 500/month. Options:
(a) paid Odds API plan; (b) single-fetcher design — one cron warms lines into a
shared Turso table, every environment reads it (one fetch cycle total), possibly
with a stretched TTL; (c) ride out September stale (key resets Oct 1).
Props key is separate and healthy — props/SGP were never affected.
